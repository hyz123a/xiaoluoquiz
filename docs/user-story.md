# xiaoluoquiz 用户故事与 MVP 需求

## 1. 产品概述

xiaoluoquiz 是面向学生或企业内部固定用户的在线笔试与练习平台。管理员维护题库、组建试卷并发布考试；学生按试卷要求填写考生信息参加正式笔试，也可以进入练习模式进行不限时刷题和即时订正。

产品的核心链路从“发布题目”调整为：

```text
题库题目 → 组建试卷 → 发布考试/练习 → 学生登录并进入 → 确认或补充试卷要求的考生信息（如学号） → 答题 → 交卷 → 评分与批改 → 查看结果
```

首期目标是先把“题目可复用、试卷可发布、考试可参加、答题可追踪、练习可闭环”做完整；批量导入作为题库维护辅助能力提供，后续再逐步增加随机组卷、导出、统计、通知和防作弊能力。

首期不开放用户自主注册。学生/普通用户账号由管理员创建，用户通过账号登录后参加正式考试和使用练习模式；管理员账号由部署初始化或已有管理员创建。登录账号与试卷中的考生信息字段分开：练习页面不再额外填写学号、姓名，正式考试是否填写这些字段由试卷配置决定，已登录账号的资料可以作为默认值。

### 1.1 产品模式

| 模式 | 主要用途 | 考生信息 | 时间限制 | 结果反馈 |
| --- | --- | --- | --- | --- |
| 正式考试 | 企业或学校发布一套试卷，学生在规定规则下完成笔试 | 由试卷配置，可选学号、姓名等字段；已登录账号资料可以预填 | 由试卷配置，支持倒计时和考试窗口 | 由管理员配置，简答题可待批改 |
| 练习模式 | 学生熟悉题型、复习知识点和重复练习 | 不在练习页面填写；已登录账号自动关联练习记录 | 默认不限时 | 单选、多选、填空题和判断题可即时反馈 |

正式考试和练习模式使用同一套题库和题目版本，但使用不同的答题规则。管理员发布的是“试卷”，普通用户默认先看到试卷或练习集，而不是直接看到一张没有上下文的题目列表。

### 1.2 技术约束

- 后端：Rust、Axum、Tokio。
- 数据库访问：SQLx（用户原文中的 `sqxl` 按 `SQLx` 处理）、PostgreSQL。
- 前端：Yew/WASM。
- 样式：Tailwind CSS、daisyUI。
- 端到端测试：Playwright；允许使用 TypeScript 编写测试和前端构建脚本。
- 本地开发：本地 PostgreSQL 或 Docker PostgreSQL。
- 部署方向：后续使用 Docker；本地、云端使用分层配置和环境变量覆盖敏感配置。

## 2. 角色与权限

| 角色 | 能力 |
| --- | --- |
| 学生/普通用户 | 使用管理员创建的账号登录，浏览已发布的试卷和练习集、按试卷要求确认考生信息参加考试、答题、交卷、查看允许公开的结果、进行不采集身份信息的练习 |
| 管理员 | 管理用户账号，维护题库，组建试卷，配置考试规则，发布和下线试卷，查看答题记录，批改简答题，查看统计和操作记录 |

所有题目状态、试卷状态、考试时间、答题次数、评分和数据可见性规则必须由后端校验，前端展示不能替代业务规则。

## 3. 账号与认证

首期不开放用户自主注册。学生/普通用户账号由管理员创建，管理员账号由部署初始化或已有管理员创建。用户登录后可以参加正式考试和使用练习模式；练习页面不再额外填写学号、姓名等考生信息。

### 3.1 账号规则

- 登录账号 `username` 全局唯一；固定学生群体可以直接使用学号作为 `username`，但 `username` 始终与密码分开。
- 角色首期支持 `student` 和 `admin`；状态首期支持 `active` 和 `disabled`。
- 学号可以作为账号资料字段保存，但它与登录账号不是同一个概念；试卷是否要求填写或展示学号仍由试卷配置决定。
- 创建账号时使用部署配置的固定初始密码。该密码只作为过渡凭证，不得与账号名相同；密码通过环境变量或部署密钥配置，不能写入源码。管理员创建账号后向用户告知账号和固定初始密码。
- 首次登录必须修改固定初始密码；在完成修改前，只允许进入修改密码流程，不能访问考试、练习和管理功能。
- 密码只保存经过加盐的密码哈希，管理员不能查看用户现有密码。管理员重置密码时将账号恢复为固定初始密码，并重新标记为“首次登录必须改密码”。
- 禁用账号后不能创建新的考试答题，也不能登录；已经完成的答题记录继续保留。
- 登录失败需要限速或临时锁定；密码重置、账号禁用、角色变更和登录事件需要写入审计日志。

### 3.2 账号管理用户故事

#### US-AUTH-01：管理员创建用户账号

**作为**管理员，我希望创建学生或其他管理员账号，以便向固定用户分发系统访问权限。

验收标准：

- 管理员可以填写登录账号、显示名称、角色以及可选的学号资料。
- 登录账号重复时创建失败，并返回明确错误。
- 创建成功后系统使用配置的固定初始密码，并将账号标记为“首次登录必须改密码”。管理员只需向对应用户告知登录账号和固定初始密码。
- 新账号默认处于启用状态。
- 创建操作记录操作者和时间，不记录明文密码。

#### US-AUTH-02：用户首次登录并修改密码

**作为**首次登录的用户，我希望设置自己的密码，以便获得只有自己知道的登录凭证。

验收标准：

- 用户可以使用管理员提供的账号和固定初始密码登录。
- 首次登录后强制进入修改密码页面，修改成功前不能访问其他功能。
- 新密码不能为空，不能等于登录账号或固定初始密码，并通过服务端强度校验。
- 修改成功后清除首次改密标记，并跳转到原本要访问的页面或首页。
- 修改密码失败时保留账号，不泄露密码相关敏感信息。

#### US-AUTH-03：管理员管理用户账号

**作为**管理员，我希望查看和管理用户账号，以便处理人员变动和账号异常。

验收标准：

- 管理员可以分页查看账号、显示名称、角色、状态、创建时间和最近登录时间。
- 管理员可以启用、禁用账号，并为用户发起密码重置。
- 管理员不能查看任何用户的现有密码或密码哈希。
- 不能删除系统中的最后一个管理员账号，也不能在没有其他管理员的情况下取消自己的管理员权限。
- 账号创建、启用、禁用、重置密码和角色变更都记录审计日志。

#### US-AUTH-04：用户登录

**作为**用户，我希望使用管理员创建的账号登录，以便参加考试和进行练习。

验收标准：

- 登录成功后建立服务端会话，服务端根据会话识别用户，不信任浏览器传回的角色或用户编号。
- 禁用账号不能登录，过期或被撤销的会话不能继续访问受保护接口。
- 学生只能访问自己的答题记录；管理员功能需要管理员角色。
- 退出登录后服务端会话失效。

## 4. 题库

题库是可被多套试卷和练习集复用的题目集合。每道题必须归属于一个题库；题目本身不保存考试分值。题目被加入试卷时，需要记录题目版本、顺序和在该试卷中的分值。系统初始化时创建“人工智能导论”和“测试题库”两个题库，后续题目由管理员录入并选择归属。

### 4.1 题目状态

题目状态首期使用以下状态：

- `draft`：草稿，仅管理员可见，不能加入已发布试卷。
- `published`：可用于组建新的试卷和练习集。
- `archived`：已下线，不再加入新的试卷，但保留历史答题记录。

已被用户作答的题目不能直接破坏历史结果。若修改题干、选项或答案会影响评分，应创建新版本，或者复制为新题；历史答题记录必须继续关联作答时的题目版本。

### 4.2 题型要求

#### 选择题

- 题目包含题干、选项、正确选项和解析。题目分值不在题目录入时配置，而是在组装具体试卷时配置。
- 支持单选题和多选题。多选题的选项数量不固定，至少有两个选项和两个正确选项；管理员录题时可以动态添加或删除选项，前端只提供 A-D 作为默认起点。
- 选项需要稳定的唯一标识，评分不能依赖选项在页面上的数组下标；多选题提交完整的正确选项集合才算正确，选项顺序不影响评分。
- 学生开始答题前不返回正确选项；根据试卷的结果规则，在交卷或批改后显示答案和解析。

#### 填空题

- 题目包含题干、一个或多个空、参考答案和可选解析。题目分值在组装具体试卷时配置。
- 一个空可以配置多个可接受答案。
- 评分前进行明确的答案规范化，例如去除首尾空白；大小写、全角半角和标点是否忽略应由题目或系统规则决定。
- 对无法可靠自动判断的答案，结果标记为“待人工确认”，不能误报为正确。

#### 判断题

- 学生选择“正确”或“错误”。
- 管理员配置标准答案和解析；题目分值在组装具体试卷时配置。
- 使用布尔语义存储答案，不依赖中文显示文字进行判断。

#### 简答题

- 题目包含题干、参考答案、评分要点或评分 rubric 和解析；题目分值在组装具体试卷时配置。
- MVP 默认采用人工阅卷，不自动把文本相似度当作最终成绩。
- 在人工评分完成前，答题记录状态为“待批改”；管理员可以补充评语和得分。

### 4.3 题目管理用户故事

#### US-QUESTION-01：管理员创建草稿题目

**作为**管理员，我希望录入五种题型（单选、多选、填空、判断、简答）的题目和答案，以便建立可复用题库。

验收标准：

- 管理员先选择题库，再选择题型并看到对应的编辑表单。
- 必填字段、题库归属、选项数量和答案格式在服务端再次校验；题目不保存分值，试卷组装时必须为每道题配置分值。
- 保存草稿不会出现在学生的试卷或练习列表中。
- 保存失败时不丢失已经填写的内容，并返回可定位的错误信息。

#### US-QUESTION-02：管理员维护题目解析和版本

**作为**管理员，我希望为题目填写解析并保留历史版本，以便学生订正，同时不影响已完成考试的历史成绩。

验收标准：

- 解析是可选的，但已发布题目可以通过新版本补充解析。
- 试卷发布后固定引用的题目版本。
- 普通用户只能在试卷或练习模式允许的时机看到解析。
- 富文本能力首期尽量使用安全的 Markdown 子集或纯文本，禁止未经清洗的任意 HTML。

#### US-QUESTION-03：管理员下线题目

**作为**管理员，我希望下线过时或有错误的题目，以便它不再被加入新的试卷。

验收标准：

- 下线题目不出现在新的组卷候选列表中。
- 已发布试卷和历史答题记录仍可读取固定版本。
- 下线不会物理删除题目、答案或历史统计。

### 4.4 题目批量导入

**作为**管理员，我希望批量导入题目，以便快速补充题库。

验收标准：

- 运行时可以在管理员题目管理页面粘贴标准 JSON 导入题目。
- 部署时可以使用 `xiaoluoquiz-import-questions <questions.json>` 命令导入同一格式的 JSON。
- 运行时接口和部署命令共用同一套服务端校验和写入逻辑。
- 导入只新增题目；同一题库内规范化后的重复题干跳过，不能覆盖或修改已有题目。
- 新导入题目默认直接保存为 `published`，可以立即用于组卷和练习；手工录入题目仍默认保存为 `draft`，不会自动发布。
- 导入结果返回新增、跳过和错误数量；存在格式或题目校验错误时整批不写入。


### 5.1 试卷状态

试卷首期使用以下状态：

- `draft`：草稿，仅管理员可见，可以调整题目和考试规则。
- `published`：已发布，学生可以在开放规则允许的范围内看到并参加。
- `archived`：已下线，不再允许新的答题，但保留已开始或已提交的答题记录。

`upcoming`、`open`、`closed` 是根据发布时间窗口计算出的运行状态，不一定需要作为数据库状态单独保存。

### 5.2 试卷配置

一套试卷至少包含：

- 标题、说明、适用岗位或班级、发布状态。
- 题目列表、题目顺序、题目版本和每道题在本试卷中的分值。
- 总分和通过分数（如果启用）。
- 答题模式：`exam` 正式考试或 `practice` 练习模式。
- 正式考试的开放时间、截止时间、答题时长和最多答题次数；开放、截止、开始和交卷时间统一按 `Asia/Shanghai`（UTC+08:00）解释和展示，数据库使用 `timestamptz` 保存绝对时间。
- 是否允许中途退出后继续、是否自动保存答案、到时是否自动交卷。
- 结果公开规则，包括成绩、正确答案、解析和批改评语的公开时机。
- 正式考试的考生信息字段配置。管理员可以按试卷选择字段，例如：
  - `student_id`：学号。
  - `name`：姓名。
- 每个考生信息字段需要配置显示名称、字段类型、是否必填、格式校验、是否参与重复答题判断以及管理员可见范围。
- 练习模式不显示和收集上述考生信息字段。
- 是否允许考前预览题目；MVP 默认可以关闭。

本项目不采集与当前考试目标无关的高敏感身份信息。若业务只需要区分学生，优先使用学号；若只需要展示姓名，则只收集姓名。

试卷发布时必须固定题目版本、组卷顺序和考生信息字段配置，不能因为题库或试卷后来被编辑而改变正在进行或已经完成的考试。

### 5.3 试卷管理用户故事

#### US-PAPER-01：管理员创建试卷草稿

**作为**管理员，我希望从题库中选择题目组建一套试卷，以便发布一次完整的在线笔试。

验收标准：

- 管理员可以填写标题、说明、答题模式、考试规则和考生信息字段配置。
- 管理员可以从可用题目中选择题目，并调整顺序和本试卷分值。
- 系统显示题目数量、总分和题型分布。
- 正式考试可以单独选择是否要求学号、姓名或其他允许的考生信息；练习模式不能配置或收集这些字段。
- 草稿试卷不会出现在学生端。
- 试卷引用的题目必须通过题型答案校验。

#### US-PAPER-02：管理员预览试卷

**作为**管理员，我希望以学生视角预览试卷，以便在发布前确认题目顺序、分值和考试说明正确。

验收标准：

- 预览显示学生实际看到的题面和答题控件。
- 预览不会修改正式答题记录。
- 预览页明确区分学生可见内容和管理员可见答案。

#### US-PAPER-03：管理员发布试卷

**作为**管理员，我希望发布一套试卷，以便学生按考试规则参加笔试或进入练习。

验收标准：

- 只有完整校验通过的草稿试卷才能发布。
- 发布时固定试卷版本、题目版本、顺序和分值。
- 正式考试必须配置开放规则，并明确本次考试要求收集的考生信息字段；不需要收集时应明确配置为空。
- 发布操作记录管理员和时间。
- 已发布试卷的关键字段不能直接修改；会影响评分的修改必须创建新版本或复制为新试卷。

#### US-PAPER-04：管理员下线试卷

**作为**管理员，我希望下线过期或有错误的试卷，以便学生不能开始新的答题。

验收标准：

- 下线后试卷不出现在新的考试入口中。
- 已开始但尚未提交的答题如何处理由试卷规则决定；MVP 按固定题目版本完成提交或自动交卷。
- 下线不会删除历史答题、成绩和批改记录。

#### US-PAPER-05：管理员搜索和筛选题库与试卷

**作为**管理员，我希望按状态、题型、模式、适用岗位和关键字查找题目或试卷，以便维护和组卷。

验收标准：

- 题库和试卷可以按状态筛选。
- 试卷列表显示标题、模式、开放时间、题目数量、总分和更新时间。
- 题干和试卷标题搜索有分页或限制，不能一次加载全部数据。

## 6. 学生端流程

### 6.1 浏览试卷和练习集

#### US-STUDENT-01：查看已发布试卷

**作为**学生，我希望看到当前可以参加的正式考试和练习集，以便选择要参加的内容。

验收标准：

- 学生必须使用有效账号登录后访问考试和练习入口。
- 学生只能看到已发布且符合开放规则的内容。
- 列表显示标题、说明、模式、题目数量、总分、答题时长、开放时间和当前参加状态。
- 没有可用内容时显示明确的空状态。
- 草稿、已下线和未开放的正式试卷不会出现在可参加列表中。

### 6.2 正式考试

#### US-EXAM-01：填写试卷要求的考生信息并开始考试

**作为**学生，我希望点击一套试卷并填写该试卷要求的考生信息后开始考试，以便系统记录本次笔试。

验收标准：

- 学生必须先登录；未登录或首次改密未完成时不能创建正式考试答题。
- 开始答题前展示考试说明、考试时间、答题时长、题目数量、总分、考生信息字段和结果公开规则。
- 系统只展示管理员为该试卷配置的字段，例如学号、姓名或其他明确字段；未配置的字段不应出现。
- 已登录账号中已有的学号或姓名可以作为默认值，学生确认后再提交；试卷要求但账号中没有的字段才需要现场填写。
- 每个字段按照试卷配置校验是否必填、长度、格式和允许字符。
- 考生信息不会被当作登录凭证或身份认证。
- 同一试卷和同一组去重字段达到答题次数上限时，不能继续创建新答题；若规则允许继续，应恢复未完成的答题。
- 创建答题记录后才进入正式答题页面。

#### US-EXAM-02：进行正式考试

**作为**学生，我希望在一张试卷中连续回答所有题目，以便完成正式笔试。

验收标准：

- 页面显示当前进度、未答题数量和剩余时间。
- 学生可以在题目之间切换，并看到已答、未答和标记状态。
- 答案按服务端规则自动保存或在明确的保存操作后保存；刷新页面不会无提示丢失已保存答案。
- 服务端根据答题记录关联的试卷版本和题目版本评分，不信任浏览器传回的分数。
- 简答题提交后状态为“待批改”，不能伪造自动得分。

#### US-EXAM-03：交卷和自动结束

**作为**学生，我希望主动交卷，或者在考试时间结束时由系统自动结束答题，以便形成最终答题记录。

验收标准：

- 主动交卷前显示未答题提醒和二次确认。
- 交卷接口具备幂等性，重复点击不会产生多份不可解释的最终记录。
- 到达截止时间或答题时长结束时，由服务端判断答题是否结束；浏览器计时器不能延长考试时间。
- 交卷后不能修改原始答案；如允许补交，必须形成新的明确答题记录。

#### US-EXAM-04：查看考试结果

**作为**学生，我希望在允许的时间查看本次考试结果，以便知道自己的成绩和需要复习的内容。

验收标准：

- 结果公开规则由试卷配置决定，可以是交卷后立即公开、人工批改完成后公开或管理员统一公开。
- 自动评分题显示得分和状态；简答题未批改时显示“待批改”。
- 参考答案、解析、评语和详细得分按规则显示。
- 学生不能读取其他考生信息对应的答题记录。

### 6.3 练习模式

#### US-PRACTICE-01：进入练习模式

**作为**学生，我希望选择练习集或题型进入练习模式，以便在正式考试前熟悉题目。

验收标准：

- 练习页面不要求再次填写学号、姓名等考生信息；已登录账号由服务端自动关联练习记录。
- 练习模式默认不限时，不受正式考试的答题次数限制。
- 可以按题库、题型、分类或标签筛选；没有筛选条件时显示全部可练习题目。
- 练习内容只能使用已发布题目或已发布练习集。
- 练习页面显示必要的加载、空状态和错误状态。

#### US-PRACTICE-02：即时订正练习答案

**作为**学生，我希望提交单道练习题后立即看到评分和解析，以便及时纠正错误。

验收标准：

- 单选题、多选题、填空题和判断题由服务端评分。
- 提交前不返回正确答案；提交后按练习规则显示对错、正确答案和解析。
- 简答题提交后显示“待批改”或“参考答案自查”，不能伪造自动评分。
- 重复提交同一道练习题不会产生重复的不可解释记录，接口需要幂等或明确覆盖规则。

#### US-PRACTICE-03：查看练习记录

**作为**学生，我希望查看自己的练习记录，以便重复训练薄弱题目。

验收标准：

- 练习模式默认不要求填写或提交学号、姓名等考生信息。
- 练习记录通过服务端会话关联当前登录账号，用户可以在其他设备登录后继续查看自己的练习记录。
- 练习记录包含题目版本、作答时间、答案、得分或待批改状态。
- 题目下线后，已经产生的练习记录仍可查看。
- 练习记录不提供按任意学号或姓名查询他人数据的入口。

## 7. 管理后台

#### US-ADMIN-01：查看管理概览

**作为**管理员，我希望看到试卷、考试参与和待批改情况，以便知道系统当前状态。

验收标准：

- 概览至少展示已发布试卷数、进行中的答题数、已提交答题数和待批改简答题数。
- 统计口径在界面上明确，例如“已发布试卷”不包含草稿和已下线试卷。
- 空数据时有明确的空状态，不显示误导性的加载中状态。

#### US-ADMIN-02：查看考试答题记录

**作为**管理员，我希望按试卷、已配置的考生信息、状态和时间查看答题记录，以便处理考试结果。

验收标准：

- 列表显示试卷、已配置的考生信息、开始时间、提交时间、答题状态、客观题得分和总分状态。
- 考生信息搜索有权限边界和分页限制，且仅展示本试卷配置的字段。
- 题目下线或题目产生新版本后，历史答题仍对应到原试卷和题目版本。

#### US-ADMIN-03：批改简答题

**作为**管理员，我希望处理待批改简答题，以便给学生准确成绩。

验收标准：

- 可以按试卷和待批改状态筛选。
- 管理员提交得分和评语前，服务端校验分值范围和答题记录状态。
- 批改操作记录管理员、时间、得分和评语变更。
- 结果公开后，学生可以看到最新批改结果。

#### US-ADMIN-04：导出考试结果

**作为**管理员，我希望导出一套试卷的考试结果，以便进行后续统计或提交给企业/学校。

验收标准：

- 可以按试卷和答题状态导出已配置的考生信息、成绩、批改状态和提交时间。
- 导出内容不包含不必要的敏感数据。
- 导出操作记录管理员和时间。

## 8. 建议的数据边界

这是实现约束，不是要求把所有字段一次性做完。推荐至少有以下实体：

- `users`：登录账号、密码哈希、角色、状态、首次改密标记、显示名称、可选学号资料和时间字段。
- `user_sessions`：服务端会话、过期时间和撤销状态。
- `question_banks`：题库名称、说明和题目统计。
- `questions`：题库题目的稳定标识、唯一题库归属、题型和当前状态。
- `question_revisions`：题干、解析、题目版本和发布信息，不保存试卷分值。
- `question_options`：选择题选项及稳定标识。
- `question_answers` 或题型专用答案字段：正确选项、可接受填空、判断值、参考答案和评分规则。
- `paper_candidate_fields`：试卷要求填写的考生信息字段定义、顺序、必填规则、格式校验和脱敏规则。
- `attempts`：一次考试或练习的 `user_id`、试卷版本、模式、考生信息快照（正式考试按配置保存，练习不采集）、开始时间、截止时间、提交时间、状态和成绩。
- `attempt_answers`：每道题的原始答案、自动评分、人工评分、评语和批改状态。
- `audit_logs`：题目、试卷、发布、下线、交卷和批改操作。

MVP 需要建立登录用户表，但不开放用户自主注册。正式考试的 `attempts` 保存 `user_id` 和试卷配置的考生信息快照；练习记录通过 `user_id` 自动关联，页面不再要求用户重复填写学号或姓名。密码只保存哈希，管理员不能读取明文密码；账号和考生信息必须限制查询范围。

服务端领域层负责题型答案、试卷规则、考试状态和评分规则的校验；数据库负责唯一性、外键、状态可表达性、版本关联和时间字段一致性；前端只负责交互和展示。

## 9. MVP 优先级

### P0：必须完成

- 管理员创建、启用、禁用和重置用户账号；用户可以登录并在首次登录时强制修改固定初始密码。
- 五种题型的题库维护：草稿、发布、下线和版本关联。
- 管理员从题库选择题目、调整顺序和分值，配置考生信息字段，创建并发布试卷。
- P0 只实现学号和姓名等必要字段，不采集与考试无关的高敏感身份信息。
- 学生端展示已发布试卷和练习入口。
- 正式考试开始前按照试卷配置填写考生信息和考试说明确认。
- 正式考试的一次答题记录、答题进度、服务端保存、主动交卷和超时自动结束。
- 单选题、多选题、填空题和判断题自动评分；简答题提交后进入待批改。
- 练习模式：不限时、按题型筛选、单题提交、即时反馈和解析展示；选择题反馈包含单选题和多选题。
- 管理员查看考试记录和批改简答题。
- PostgreSQL migrations、本地初始化脚本、本地配置和生产配置模板。
- 领域测试、API 集成测试、真实 PostgreSQL 仓储测试和 Playwright 端到端测试。

### P1：建议随后完成

- 试卷搜索、筛选、分页和预览。
- 分类、标签、难度、练习集和错题本。
- CSV/Excel/JSON 导入导出。
- 随机组卷、题目乱序、选项乱序和不同学生不同试卷。
- 考试结果统计、成绩分布、按题目分析和管理员报表。
- 重复参加规则的高级配置、访问口令、通知和批量批改。

### P2：按实际使用再评估

- 用户自助注册、账号绑定和更细粒度管理员权限。
- 摄像头、录屏、切屏检测、浏览器限制等防作弊能力。
- 编程题、文件上传题和复杂系列题。
- Redis、消息队列、全文搜索或独立对象存储。
- 与企业招聘、学校教务或 ATS 系统对接。

## 10. 未决事项

以下事项在开始实现对应功能前需要确认：

1. MVP 使用部署配置的固定初始密码，管理员创建账号后直接告知用户；仍需确认是否需要批量创建、批量打印或其他发放方式。
2. 固定初始密码的配置位置、是否轮换，以及密码泄露后如何批量处理尚未完成首次改密的账号。
3. 账号资料是否包含学号、姓名等字段，以及这些资料是否可以作为试卷考生信息的默认值。
4. 正式考试支持哪些考生信息字段：学号、姓名、班级等；每个字段的默认必填状态和校验规则是什么。
5. 同一试卷按照哪些去重字段限制参加次数：只允许一次、允许重新开始，还是允许恢复未完成答题。
6. 考试窗口和答题时长的关系：统一时间结束，还是从开始答题起计时。
7. 浏览器刷新、关闭页面和网络中断时，答案保存和恢复的具体规则。
8. 成绩、正确答案、解析和简答题评语的公开时机。
9. 练习模式默认通过登录账号自动关联记录，不重复填写考生信息；是否允许未登录匿名练习。
10. 是否需要随机组卷和题目/选项乱序；当前建议 P0 使用固定试卷，P1 再增加随机化。
11. 是否需要导入现有题库；若需要，应先确定 CSV/JSON/Excel 格式和题目版本规则。
12. 考生信息属于个人信息，正式部署前需要确定访问控制、保存期限、导出权限、脱敏展示和删除规则。

## 11. 竞品参考与取舍

本产品可以参考牛客的“题库—组卷—考试—结果分析”链路，但不直接复制其面向大规模招聘和防作弊的全部能力：

- 牛客企业版将题目录入和试卷组卷分开，并支持通过题目备注等方式快速筛选题目组卷。
- 牛客公开的校招笔试案例包含固定开考、开放时间窗口内自由开始、固定答题时长以及随机试卷等不同考试安排。
- 牛客还将考前预览作为可配置的考试能力，并提供岗位对应的组卷策略和结果分析。
- xiaoluoquiz 面向约 200 名固定用户，首期优先实现固定试卷、按试卷配置收集考生信息、答题记录、自动评分、人工批改和练习模式；随机组卷、防作弊监控、复杂题型和招聘系统对接放到后续阶段。
